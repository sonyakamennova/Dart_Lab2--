# ToDo-приложение (Лабораторная работа №2)

Консольное ToDo-приложение на языке Dart, позволяющее добавлять, просматривать, отмечать выполненными и удалять задачи с использованием классов и цветного вывода в терминале.

## Запуск
1. Клонировать репозиторий: `git clone <ссылка_на_ваш_репозиторий>`
2. Перейти в папку: `cd lab2_todo`
3. Установить зависимости: `dart pub get`
4. Запустить: `dart run`

## Что изучили
* Создание классов в Dart, объявление полей и написание кратких конструкторов с именованными параметрами (`required this.title`).
* Написание методов класса и переопределение стандартного метода `toString()` с помощью аннотации `@override`.
* Использование геттеров (`get`) для вычисляемых свойств и статических полей (`static`) для хранения общих данных класса.
* Обеспечение приватности идентификаторов в Dart с помощью нижнего подчёркивания (`_`).
* Подключение и использование сторонних пакетов с `pub.dev` через `pubspec.yaml` и `dart pub add`.

## Ответы на контрольные вопросы

**1. В чём разница между полем класса и обычной переменной в функции?**
Обычная (локальная) переменная создаётся внутри функции и уничтожается сразу после завершения её работы. Поле класса принадлежит конкретному объекту (экземпляру класса), хранит его состояние и существует в памяти столько же, сколько живёт сам объект.

**2. Что такое конструктор и зачем он нужен?**
Конструктор — это специальный метод, который автоматически вызывается при создании нового объекта класса. Он нужен для начальной инициализации всех полей объекта и проверки того, что обязательные данные переданы при создании.

**3. Зачем нужен `@override` перед `toString()`? Что будет если его убрать?**
Аннотация `@override` явно указывает компилятору, что мы переопределяем метод родительского класса `Object`, и защищает от случайных опечаток в имени метода. Если её убрать, код продолжит работать (так как сигнатура совпадает с `Object.toString()`), но компилятор не предупредит, если случайно допустить ошибку в названии метода, а анализатор (линтер) выдаст предупреждение.

**4. Чем статическое поле `static int _counter` отличается от обычного поля? Сколько копий этого поля существует в программе?**
Обычное поле создаётся отдельно для каждого объекта класса, поэтому у каждой задачи свой `id` и свой `title`. Статическое поле принадлежит самому классу целиком, а не отдельным объектам — в программе существует ровно **одна копия** этого поля, общая для всех экземпляров класса.

**5. Что означает нижнее подчёркивание в `_counter`?**
Нижнее подчёркивание `_` перед именем делает поле, метод или класс приватным на уровне библиотеки (файла `.dart`). Это значит, что к `_counter` можно обращаться только внутри того файла, где он объявлен (`lib/todo.dart`), а из других файлов (например, из `bin/lab2_todo.dart`) он недоступен.
